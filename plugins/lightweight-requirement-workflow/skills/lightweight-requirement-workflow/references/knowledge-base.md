# 知识库草案与回写

## 两阶段规则

1. 草案阶段：读取已确认的 PRD、用户故事、原型说明、评审和自检，只生成 `knowledge_base_draft.md`，不修改知识库。
2. 回写阶段：只有用户明确确认草案后，才修改 `documents/knowledge_base/`。

“继续”“好的”“文档确认”不等于确认知识库回写。确认对象必须明确指向知识库草案。

## 草案内容

按目标文件列出新增、更新、保持不变和不写入项：

- `product_profile.md`：稳定的产品定位、目标用户或核心价值变化。
- `feature_map.md`：已确认进入产品基线的功能模块。
- `design_decisions.md`：关键决策、理由、适用范围和替代方案。
- `design_system.md`：可跨需求复用的 UI/交互规范，不沉淀一次性视觉。
- `glossary.md`：稳定术语、定义和禁用同义词。

不要把未决项、临时演示数据、工程猜测、真实联系人或一次性排期写入知识库。

## 回写

- 回写前重新读取目标文件，保留用户已有内容。
- 增量编辑，不重写整个知识库。
- 对重复或冲突条目先报告并等待决定。
- 写入后列出实际新增和更新内容，并记录 `knowledge_base_write` 门槛。

用户取消回写时，将 `knowledge_base_draft` 记为 `cancelled`，保留草案作为需求记录并结束流程。
